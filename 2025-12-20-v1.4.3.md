Major **performance improvements** for the calendar system with intelligent caching and optimized queries.

## Performance
- **REST API Response Caching**: Calendar events API now caches responses for 5 minutes using WordPress transients
  - Subsequent requests to the same date range return instantly from cache
  - Cache automatically invalidated when events are saved, deleted, trashed, or untrashed
  - Cache cleared when calendar-related settings are updated
- **Query-Level Calendar Filtering**: Events not displayed in calendar are now filtered at the database query level using `meta_query`, significantly reducing processing
- **Batch Meta Loading**: All post meta for calendar events loaded in a single query using `update_meta_cache()`, eliminating the N+1 query problem
- **Request-Scoped Caching**: Global options, anchor dates, display fields config, and permalinks are now cached per-request
- **Immediate Calendar Render**: Calendar renders immediately on page load with event prefetching moved to background
- **Script Defer Strategy**: All calendar scripts use `defer` loading on WordPress 6.3+

## Added
- `EventsEndpoint::clear_cache()` method for programmatic cache clearing
- `EventsEndpoint::register_cache_hooks()` method for automatic cache invalidation
- `lre_calendar_cache_cleared` action hook fired when cache is cleared

## Changed
- Automatic cache invalidation on event save/delete/trash/untrash
- Cache cleared when calendar-related settings are updated
